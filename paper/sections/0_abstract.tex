Mega-constellation deployments at 550--1200\,km altitude are transitioning LEO
satellite networks from bent-pipe relays to multi-hop IP backbones. 3GPP
NTN standards now mandate in-orbit forwarding, but open inter-satellite links expose
on-board routers to eavesdropping, injection, and replay. Radiation-hardened
on-board processors cannot sustain conventional per-flow security such as
IPsec or DTLS. This paper presents \textbf{6FLAS}, a lightweight stateless
mechanism that repurposes the 20-bit IPv6 Flow Label as a connectionless flow
authenticator and binds it to an SRv6 Security SID. Each on-board router
verifies a single keyed MAC over the authenticated routing context (IPv6 addresses, Flow Label, and active SRv6 segment) and probes a small
per-$(\textsf{domain}, \textsf{direction})$ replay window; no per-flow security association is maintained.
We analyze 6FLAS against forgery, replay, man-in-the-middle, and stateless
denial-of-service attacks. On a 1\,GHz space-grade core, 6FLAS reduces per-hop
processing by $6.0\times$ versus an SRv6 HMAC
baseline and by $55\times$ versus IPsec~ESP (which additionally encrypts payload). Header overhead drops by $76\%$, and per-flow on-board state
is eliminated entirely. A C microbenchmark empirically confirms the structural ordering
$\text{FLAS} \ll \text{SRv6-Sec} \ll \text{IPsec}$. End-to-end latency remains
propagation-dominated across a 1584-satellite Walker-delta constellation. The baseline design assumes each domain has a single authoritative packet source or a coordinated source set, consistent with typical managed ground-segment architectures; fully decentralized multi-sender domains require additional coordination mechanisms or per-flow state fallback.
